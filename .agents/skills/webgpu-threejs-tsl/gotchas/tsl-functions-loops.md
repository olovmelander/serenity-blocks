# TSL functions, loops and uniform tables

Read before writing a shared helper `Fn`, giving one a `setLayout`, looping over event rows or fixed slots, or packing data into `uniformArray`s; and when the WGSL is tens of KB, a pipeline takes seconds, or the parser reports an unresolved `nodeUniformN`.

**The rule of thumb.** A helper called more than once gets `setLayout` (one real shader function instead of a copy per call) and must then be PURE and FLAT: every value comes in as a parameter (no captured uniforms or textures), it calls no other laid-out helper, and its parameter names are not words WGSL or GLSL reserve. A helper that reads the uniform bag or a texture stays an inline `Fn` or a plain JavaScript function. Data for many things goes in ONE `uniformArray` of `vec4` rows read by ONE `Loop` to a live count.

One gotcha per line; the number is the row's permanent id (cited elsewhere as "gotcha #NN"). Rows numbered below 300 were numbered before these files existed and keep their numbers, in no order. A NEW row goes at the END of this table and takes the next free number in **400–499**. To search: `node .claude/skills/webgpu-threejs-tsl/scripts/gotcha.mjs <words>` (`README.md` in this folder).

| # | Symptom | Cause | Fix |
|---|---|---|---|
| #81 | Fragment WGSL is huge (tens of KB) with no `fn` definitions; compile slow | A TSL `Fn` **without `setLayout`** is an *inline* function — its body is re-emitted at every call site (a 20-call simplex lake fragment was 113 KB) | Give every shared helper `Fn` a `setLayout({ name, type, inputs })`; with it the builder emits one real WGSL `fn` (14 KB, 1.9 s instead of 3.7 s on the same lake) |
| #93 | `Error while parsing WGSL: unresolved value 'nodeUniformN'` inside a function you gave `setLayout`, and the material's pipeline is invalid | The laid-out `Fn` samples a **texture** captured from the enclosing scope. r186 emits the body as a real WGSL `fn` that names the texture binding, but the binding is not declared for that module (verified 2026-10-05 with `texture(tex, uv).level(0)` in a `setLayout` helper; the same helper inline compiled) | Keep textures out of laid-out helpers: sample in the caller and pass the value in, or replace the lookup with arithmetic. Pass event/uniform values in as parameters too (one `vec4` built once per fragment) rather than closing over them — that keeps the helper a pure function. Precedent: `caveEnvironment` in `src/themes/crystal-cave/crystal-cave-light.js` |
| #95 | `Error while parsing WGSL: unresolved value 'NodeBuffer_…'` or `struct member nodeUniformN not found` after giving a shared helper `setLayout` | A `Fn` with a layout is generated once and its code is reused by every later material; uniforms and uniform arrays it captured from its closure are only declared in the first shader that built it | Keep layout functions pure — pass values in as parameters, as `chapter-environments/shared/odyssey-tsl-noise.js` does — and leave helpers that read uniforms as inline `Fn`s (a `Loop` inside an inline `Fn` is fine). Precedent: `src/themes/sakura-twilight/sakura-light.js` |
| #207 | On the **WebGL2 backend** a heavy material compiles **twice** on first use (cold: tens of seconds of frozen main thread), though its version never changes and the scene has one draw of it | The material is built twice (a prewarm or `compileAsync`, then the render), and a laid-out `Fn` that **calls another laid-out `Fn`** makes the two builds emit their helper functions in a different order: the GLSL text differs, so ANGLE's program cache misses and the whole program compiles again. WebGPU hides it (it compiles fast) | Keep laid-out helpers flat: inline the inner helper's arithmetic instead of calling it (the spot cluster now hashes inline). Find it by wrapping `WebGL2RenderingContext.prototype.getProgramParameter` and logging slow links with their source lengths: two links of one length with different text is this. Precedent: `rbSpots` in `src/themes/rainbark/rainbark-tsl.js` (2026-10-13, the near bark 9–13 s twice → once) |
| #178 | A laid-out TSL helper compiles to WGSL but GLSL fails around a parameter called `input` | GLSL reserves `input`; a `.setLayout()` parameter name becomes shader source | Use a neutral parameter such as `cIn`, and compile the actual WebGL2 backend. Found on Painted Ages' filmic helper (2026-10-12). This does not prohibit the documented BloomNode hook's JavaScript destructuring field `input`, which is not a shader parameter. |
| #223 | A material draws nothing and the console shows `Error while parsing WGSL: … error: 'from' is a reserved keyword` (then an invalid render pipeline and command buffer every frame) | A laid-out helper's parameter has a name WGSL reserves. The builder prints `setLayout` input names as given, and WGSL reserves many ordinary words: `from`, `of`, `type`, `set`, `get`, `use`, `target`, `filter`, `self`, `match`, `mod`, `module`, `move`, `new`, `null`, `pass`, `resource`, `smooth`, `with`, `where` and more. Only Tint rejects it; a Node build of the graph is clean | Name parameters neutrally (`cA`, `cB`, `k`), and gate it: check every `fn <prefix>_*` signature in the dumped WGSL and GLSL against a reserved list (`RESERVED` in `tests/unit/murmuration-shaders.test.js`). Found on Murmuration's heat hue turn (2026-10-21), `murm_turnHue` in `src/themes/murmuration/rendering/fluid-particles-renderer.js` |
| #101 | A fragment module of 100–180 KB of WGSL with hundreds of `var<private>` declarations; slow pipeline creation | A JS `forEach` that emits a feature's TSL once per element (47 painted crystals, 84 loop segments, 30 leaves) inlines every copy and hoists all its variables: a 135 KB `main()` with 974 private variables | One TSL `Loop` over the same values in a `uniformArray` (or derived from the loop index), and repeated bodies as pure laid-out `Fn`s. Four breathing worlds' largest modules went from 139–176 KB to 31–64 KB with frames identical to rounding (`worlds/storm.js`, `crystal*.js`, `solar.js`, `zen.js`, 2026-10-05). Measure with `scripts/capture-breathing-headless.mjs --shaders` |
| #162 | A dozen fixed slots (12 bow strokes, each with a colour row; 8 shadow casters per mist shelf) must be read per pixel and the fragment stage balloons | A JS loop over `uniformArray(rows, 'vec4')` with constant indices builds cleanly in both `WGSLNodeBuilder` and `GLSLNodeBuilder` but unrolls (~1.1 KB of WGSL per slot); nested in another unrolled loop it multiplies | Read the slots in one TSL `Loop(count, ({ i }) => …)` with `element(i.add(first))` (dynamic indexing of a uniform array works on both backends): Rainbow Terraces' dome fragment went from 75 KB to 40 KB of WGSL when the 12-stroke mask and the 3 × 8 caster tests became real loops. `src/themes/rainbow-terraces/rainbow-terraces-tsl.js` (`strokeMask`, the Deep's shelves) |
| #155 | `TypeError: Cannot read properties of undefined (reading 'mul')` from inside a `Loop` body as the material builds | The loop was given a `name` (`Loop({ start, end, type, condition, name: 'pr' }, …)`), and a named loop hands its index over under that NAME: `({ i })` is undefined | Destructure the name: `({ pr: i }) => …`, or leave `name` out to get `i`. Nested loops need distinct names, so they always need this. Found building `solar-eclipse-sun.js` (2026-10-11) |
| #110 | A renderer-free module must own data a shader reads as a uniform array | — | `uniformArray(rows, 'vec4')` copies `.x .y .z .w` from whatever objects the array holds (`UniformArrayNode.updateBuffer`), so plain `{ x, y, z, w }` rows written in place by a three-free module work on both backends. Keep live rows compacted at the front, pass the count in a uniform and loop `Loop({ start: int(0), end: int(count), type: 'int', condition: '<', name: 'row' }, ...)`: idle slots then cost nothing (a zero-strength row still costs its arithmetic). Give nested loops distinct `name`s. Precedent: `src/themes/fluid-dreams/fluid-dreams-choreography.js` |
| #102 | Pipeline creation fails WebGPU validation after splitting a material's data into many `uniformArray`s (the WebGL2 backend may still draw) | Each `uniformArray` is its own uniform buffer and a shader stage may bind 12 (`maxUniformBuffersPerShaderStage`); the object's own buffer counts too, so 13–15 arrays fail | Pack a feature set into ONE array of `vec4` rows addressed by block/stride/offset. Precedent: `row(block, i, k)` in `src/ui/effects/breathing/worlds/solar.js` |
