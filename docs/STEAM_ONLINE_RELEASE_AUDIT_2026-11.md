# Steam, records and online release audit

**Hold release.** On 18 November 2026, main at `8dc68d825` fails the production gate for the missing App ID and privacy contact. Even with both supplied, the current binding cannot publish a global score, two machines can discard independent offline progress, and the two-account relay test is still open.

The [release plan and operator script](STEAM_ONLINE_RELEASE_PLAN_2026-11.md) give the proposed fixes, partner-site entries, owner decisions and live acceptance tests. File and line references below are for the audited revision. The partner configuration, a licensed build, live Steam and Deck hardware were unavailable for inspection.

### Launch outside the client

The ordinary packaged path calls `restartAppIfNecessary(id)` before `init(id)`, quits on a true result and otherwise proceeds. It runs after the first window loads and the process has taken the single-instance lock. A relaunch should be checked for a flash, a loop, or the Steam-launched process handing focus to the exiting one. A store build can bypass that check entirely. `SERENITY_DISABLE_STEAM_BOOTSTRAP=1` returns from `initSteam` before the relaunch check even for a real-ID package. The restart method is also optional-chained, so a missing export skips it. The plan scopes the development override, validates the required export and tests both launch origins with the actual depot. Valve documents that a stray `steam_appid.txt` makes the restart check return false. `electron/main.js:79,909,931`, `electron/steam-integration.js:536,540,723`, `electron/steam-app-id.js:57`. [Valve's restart contract](https://partner.steamgames.com/doc/api/steam_api#SteamAPI_RestartAppIfNecessary)

### Why the relay binding is an incomplete model for leaderboards

I resolved the three interface accessors (`SteamUserStats_v012`, `SteamUtils_v010`, `SteamFriends_v017`, each prefixed `SteamAPI_`) and the find/create, upload, download, entry, count, sort/display and result functions in the installed Windows DLL. The same names exist in the shipped Linux ELF dynamic symbol table. The relay calls return synchronously. A leaderboard call returns an asynchronous handle. The npm-pinned wrapper runs callbacks at 30 Hz. Its Rust dispatcher retrieves **every** completed call result before looking up the registered handler for that handle. Two independent readers of the default pipe can race, including when a lobby call completes alongside a score. Use one callback owner. This is an implementation inference from the pinned code. A real Steam completion is still outstanding. `electron/steam-relay-transport.js:93`, `node_modules/steamworks.js/index.js:28`, `docs/OWNER_DECISIONS_RESEARCH_2026-10-13.md:200`.
