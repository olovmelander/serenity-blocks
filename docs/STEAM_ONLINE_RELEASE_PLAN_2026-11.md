**For owner approval · 18 November 2026.** The [audit](STEAM_ONLINE_RELEASE_AUDIT_2026-11.md) records current behavior at `8dc68d825`. The tables below specify a proposed launch build. They can be used to enter the partner configuration once the decisions are approved. The current release gate correctly refuses production packaging.

## 2. Cloud, stats and achievements

**Durability contract.** A successful local save survives a failed upload, an older remote snapshot, one damaged copy, a concurrent session and an answered-twice callback. Every competitive PB has its own durable entry, including a longest run that falls outside the highest-scoring 100. Local replay availability is independent. A first-ever offline guest owns a local profile. A confirmed prior account may accrue work offline in its own partition. Explicitly offer migration of legacy local saves and preserve their originals. Ambiguous guest or 480 data cannot be attributed automatically to the next Steam account.

1. Extend the existing IndexedDB completion transaction to hold a stable result receipt and pending board/stat work. Supply a UUID at run start, retain it through retries/resume and use one stable per-account match ID across FFA rounds, retransmissions and host migration. Make completion a unique upsert. Import earlier Odyssey storage and the existing high-score/aggregate formats with a crash-resumable marker. Key new Steam state and local player profiles by the real account. A shared device must switch partitions before starting sync.
2. Keep Cloud's **Remote Storage API**. Read the seven legacy files, classify explicit absence, failed read, valid known version, future version and corrupt content separately. Validate schema, per-file size, fields, digest and generation before applying. Preserve the raw failing bytes in a private local recovery copy, keep the last good local and remote versions, and tell the player when recovery is needed. An invalid manifest triggers enumeration/reconstruction from validated payloads. Missing metadata confers no permission to replace unread data. Honor account-level and app-level Cloud switches, and distinguish unknown quota from zero.
3. Prevent racing writers from replacing the last copy of a record. Give each installation its own writer ID, account-scoped record files and monotonically numbered generations. Keep two verifiable generations or immutable segments for each writer, with the previous good generation available until the new one has been written and verified. Enumerate writer files independently of a shared manifest. Merge **all** surviving valid writer contributions, then publish the union as needed. Local read-back acknowledges Steam's local storage stage. A successful Cloud upload on exit and read on a fresh machine prove the remote stage. Never delete the only copy on a failed write, quota exhaustion, an older device's return or a retry. Size and compact the format against D8 with interrupted compaction tests. [Valve Cloud configuration and timing](https://partner.steamgames.com/doc/features/cloud) · [Remote Storage API](https://partner.steamgames.com/doc/api/ISteamRemoteStorage)
4. Deduplicate new runs by durable run/match ID across cloud generations, including a rejoined match seen on two devices. Merge scores by per-board max/min, top 100 per mode by union and stable tie-break, unlocks and Stillfall solved IDs by union. Preserve current-journey reset intent separately from lifetime PBs. Keep local replay references when present and export only portable record fields. Restore individual settings/keybind edits over first download and include gameplay pad bindings. Keep raw history/replays, chat, mute list and practice logs out of Cloud.
5. Totals require attribution. Import legacy cumulative snapshots once as a shared baseline, taking the larger comparable values and keeping backups. Add new *distinct* results on top of that baseline. A per-writer subtotal or compaction checkpoint must retain enough receipt identity to deduplicate retries and cross-device FFA delivery. Historical aggregates contain no IDs to reconstruct already-lost independent games. Surface an unresolved legacy conflict and preserve both originals. Test the common-10 plus A1 plus B1 case as exactly 12. PBs can still use strict max/min.
6. Use one serialized stats writer after stats-ready for the correct App ID/user. Derive **absolute targets** from reconciled totals, compare against Steam's current values, set changed fields, then perform one StoreStats for the batch. Wait for `UserStatsStored_t` for the active App ID. The callback carries no SteamID or batch ID. Associate it with the single pending batch and active login generation, discard results crossing a logout, handle `InvalidParam` by re-reading server values/constraints, verify by read-back, and only then acknowledge the local receipt. Requested/stored are different stages. Replays of the same batch set identical targets. After a timeout, restart or ambiguous acknowledgement, read and recompute before retry. Preserve higher confirmed lifetime values. With Cloud disabled or conflicting histories that cannot be reconciled, keep contributions local and pending. Steam's per-machine stat merge chooses the more advanced set and cannot by itself sum independent offline histories. Deliver the cumulative target when ownership and reconciliation are established. [Valve stats lifecycle and offline merge](https://partner.steamgames.com/doc/features/achievements) · [StoreStats results](https://partner.steamgames.com/doc/api/ISteamUserStats#UserStatsStored_t)

The recovery guarantee requires at least one surviving valid copy. Loss of every device and Cloud copy, a manually deleted account, or an explicit decision to discard all copies cannot be repaired by a client-only game. Treat a save error as visible and retryable. Never label a game “saved” or “synced” beyond the stage actually reached.

## 6. Live test script for two accounts

**Equipment.** PC1 with account A, PC2 or Deck with account B, the accounts initially friends. Use different networks, for example B on a hotspot. Give both accounts a license and the same beta Build ID. For Cloud, quit B and sign **A** into machine 2 in a fresh test OS profile. That phase tests one person's saves across computers. Return to B afterward. For account-switch isolation deliberately use the same test OS profile in case T8. Use separate QA saves and copies throughout.

**Capture before each case.** Record time, OS/device, Steam Online/Offline Mode, App ID, Steam Build ID, commit, network, selected depot, account alias, graphics profile, Cloud switches and flag matrix.
